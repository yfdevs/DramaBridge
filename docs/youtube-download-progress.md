# YouTube 下载进度取值

2026-11-12 使用 REA 检查本机百度网盘 8.9.7（Electron 22.3.27，CDP 9337）。

REA 捕获的 `core.asar/57.js` 中，`computedProgress` 对运行任务优先读取
`runningFilesMap[id]` 的 `finish_size / size * 100`，否则读取任务或 `fileMeta`
中的同名字段；客户端用 `Math.floor` 显示整数百分比。速度由 `rate` 转换，
目录任务的实时速度另有子任务汇总逻辑。大小单位按 1024 换算。

现有只读适配器通过主进程 `$downloader.getDownloadTasks` 获取任务快照，
保留 `size`、`finish_size`、`rate`；匹配时同时限定任务名称和下载目录。
现场快照为 `size=4768412310`、`finish_size=4768182934`，比值约 99.995%。
这些值是一次快照，不代表后续时刻的进度，也不建立与界面实时事件同步的保证。

应用原公式在计算百分比后又除以 10，导致 40.1% 被显示为 4.0%。
修复后按字节数计算 0–100 的百分比，保留一位小数；YouTube 界面也优先用字节数
修正旧运行记录中的百分比。未获得有效总量时显示“正在获取下载进度”，不估算进度。
客户端整数向下取整与本应用一位小数四舍五入会有显示精度差异，此外仍存在轮询延迟。
下载到 100% 不等于整个任务完成，后续素材校验、视频处理和上传继续使用各自状态。

证据：REA `inspect_electron_page`，
`ev_7d12437cc38fa7d5813588abf494fd3dc7825d25e7ba417fce55127b5b06b00e`。
该捕获通过 CDP 读取加载的脚本，不执行页面代码；脚本路径本身不证明其来源文件与磁盘字节一致。
另外使用项目现有只读适配器读取了上述原始任务快照。
