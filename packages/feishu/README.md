# 飞书管理

`@dramabridge/feishu` 为各平台共用的主进程/服务端 API 包。`src/tables/` 管理 Wiki 节点解析、电子表格读取、单元格回写和样式。平台任务规则不放在此包。

## 配置

全局配置中的“飞书表格”填写用户自己的 App ID、App Secret 和表格 URL，使用页面顶部的“保存”统一保存，“取消”放弃修改。密钥由 Electron safeStorage 加密后通过 electron-store 保存在本机，不在源码、环境变量、安装包或日志中存放。密钥保存后不返回 renderer；密码框显示掩码，未输入新密钥时保留已保存的凭证。

各平台配置管理中的二创/转存任务设置工作表名和读取间隔（10–3600 秒，默认30秒）。默认工作表为 `快手二创`、`微信二创`、`tiktok转存`。下一次开始处理生效。飞书后台需要发布应用、开通 `wiki:node:read` 和 `sheets:spreadsheet` 并给应用授予目标表格编辑权限。

快手固定语义列：`剧名`、`集数`、`原百度链接`、`二创百度链接`、`备注`；可选 `版本1`、`版本2` 等。按表头匹配，不依赖固定列序。第一行为表头，一行一个任务。已有结果或备注的行跳过；失败后备注标浅红，清空备注重试。所有版本的名称和分享链接汇总到二创百度链接单元格。

微信固定列为 `剧名`、`集数`、`原百度链接`、`二创百度链接`、`备注`，转存前60%集数。TikTok 固定列为 `剧名`、`集数`、`原百度链接`、`单层文件夹链接`、`备注`，转存全集。后二者回写单个分享链接；保留原有平台的目标目录与视频处理规则。

三个平台均等待剧名、集数和原百度链接填齐后领取。共用 `electron/integrations/feishu/task-runner.ts` 的轮询、回写与恢复机制，平台适配器注入结果列、集数比例及转存函数。微信/TikTok检查点按平台隔离；快手保留原检查点表。各平台通过独立IPC和服务调用，网盘操作仍走既有互斥队列。任一表格任务运行时不能修改全局飞书凭证。

分享以任务文件夹为单位，保留二创任务的“封面 / 成片60%”层级及TikTok单层视频目录。分享前核验目录仅包含本任务确认的内容，发现其他文件则拒绝分享，不删除用户文件。旧的平铺链接不自动覆盖；清空结果单元格后重新处理，会复用并核验网盘文件，重新生成目录分享。

## 执行与恢复

点击开始后立即读取，串行处理本轮任务，再按间隔检查新任务。停止会停止领取，等待当前剧目完成回写。退出时受桌面应用既有15秒退出时限约束；每个版本完成后保存SQLite检查点，下次开始复用已完成版本。转存完成而飞书不可用时只重试回写，不重复转存。旧Excel任务历史保留，但不再自动执行。

来源检查点包含文档、工作表、剧名、集数、源链接、版本；回写前重新定位唯一匹配行，移动行可继续，修改/删除/重复会阻止回写。飞书 Sheets 没有按业务条件原子更新能力：请勿同时在多台设备启动同一表，处理时不要修改当前任务内容或并发排序。权限、网络和回写失败显示在页面并定期重试。

认证使用官方 `https://accounts.feishu.cn/oauth/v3/token`；短期凭证按返回的 expires_in 缓存。API请求30秒超时，仅失效凭证自动刷新一次；不盲目重放不确定是否已成功的写请求。

验证：`pnpm --filter @dramabridge/feishu check`、`build`、`test`；根目录 `pnpm exec tsx --conditions=development --test tests/electron/kuaishou-feishu.test.ts`。
