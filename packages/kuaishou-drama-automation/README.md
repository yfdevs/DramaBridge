# Kuaishou Drama Automation

快手短剧自动化运行时包。

快手二创素材任务：每个尚未分享的版本均使用原始下载海报作参考，由全局配置的 AI 图片模型替换画面内剧名，生成 9:16 竖屏海报，最终保存为 `封面/封面.png`（1080×1920）。保持原版人物和视觉风格，长标题完整保留。仅校验图片可读性、竖屏和尺寸，文字准确性由生成模型决定，不另做 AI 内容验收。AI 调用与图片失败使用全局封面重试次数，失败阻止上传并保留视频。

已生成海报按原图内容、版本名称、模型和提示词缓存；版本检查点记录成品哈希，上传重试无需再次生成，即使原素材已移除也可继续。旧的未分享任务会补生成，已成功分享的版本保持完成状态。视频继续按内容进行百度网盘云端复制，各版本的新海报单独上传；缓存目录不进入分享文件夹。

当前已实现：

- 快手经营者平台登录态复用和基础表单填写。
- 接入 `/dramaAiRpa/kuaishou` 后端接口：读取启用账号、查询 READY 任务、领取任务，并回写成功或失败结果。
- 每个启用账号使用独立浏览器登录态并持续轮询任务，轮询间隔由桌面端配置控制。空闲轮询只访问任务接口，
  不刷新或跳转浏览器页面；领取到任务后会新建专用标签页处理，并在任务结束后关闭。
- 任务通过 `publishType` 选择发布“付费”“广告”“三个广告版本”“五个广告版本”“六个广告版本”“八个广告版本”或“全部”；字段缺失、`null`、空字符串或“全部”时按顺序发布 1 个付费版本和 8 个广告版本。
- 原始付费版和广告版使用标准封面；第二至第八广告版分别使用 AI 按无字要求生成的横版短剧封面和无字竖版单集封面。
- 快手短剧封面固定准备为页面裁剪比例 `414:258`、`2208×1376` 横图；批量设置的单集封面固定准备为 `224:300`、`1792×2400` 竖图。
- 同时找到横图和竖图时不调用 AI；只有竖图时通过全局 AI 图像模型生成横图，只有横图时生成竖图。现有素材会完整适配到目标比例，空余区域使用柔化背景补齐，避免裁掉人脸、剧名或关键道具。
- AI 结果按原图内容、图像模型、剧名、目标类型和提示词版本缓存；必须补图但 AI 配置不可用或生成失败时，任务不会进入平台提交阶段。
- 快手 AI 封面生成后直接用于上传，不做文字、人物或构图的 AI 内容验收，也不因内容检测结果反复重画。仅检查图片可读性、目标尺寸和文件大小；实际生成或图片处理失败仍沿用全局封面重试配置。平台审核不通过时由人工调整封面。已有生成缓存继续复用。
- 多版本逐个执行，某个版本失败后仍继续其余版本；全部执行后，全部成功才回写任务成功；若已有版本提交或提交结果不确定，则保留本地记录等待人工核实，不自动回写失败或重复上传。提交前失败会汇总原因回写。
- 上传前查询使用的任务页关闭、崩溃或引用失效时，在当前浏览器内新建任务页并重试查询一次；下载与封面准备后再次确认任务页可用。上传提交本身不会自动重放。自动化连接整体断开时停止后续页面操作，保留已成功版本，并标明后续版本未执行；日志区分服务主动停止与意外断开。
- 每次执行（包括失败重试）先按精确剧名和售卖类型分页查询平台已有版本：审核中、发布中、发布成功的版本直接计入成功并跳过上传；待提交草稿复用原记录继续上传；审核未通过、状态未知或查询异常不会误判成功。全部版本已提交时，无需下载或准备本地素材即可回写成功。
- 任务可提供 `baiduPanResourceLink` 百度网盘分享文本。开始填写表单前会先下载到
  `localEpisodeVideoRoot/originalTitle`，并严格校验第 1 集至任务总集数是否完整、是否存在重复集数，
  同时从文件名或目录名包含“封面”或“海报”的图片中自动匹配短剧封面和单集封面；快手海报图片无需上传。
- 导演和编剧姓名固定使用“米苏”，制片人姓名使用制作机构名称，性别均默认选择“男”。
- 主要演员无需任务配置，固定生成两人：姓名均为“米苏”，分别为“男/主角”和“女/配角”。
- 授权推广材料和短剧制作协议/权属声明固定使用包内 `src/assets/授权推广.jpg` 和
  `src/assets/短剧制作协议.jpg`，所有任务共用，不读取后台版权文件字段。
- 百度网盘下载失败按 `baiduNetdiskDownloadRetryAttempts` 重试；链接无效、登录过期、剧集目录不存在、
  集数重复或缺集属于不可重试的数据错误，会直接上报任务失败。
- 批量视频上传完成轮询由 `videoUploadTimeoutMinutes` 控制，默认 120 分钟。
- 根据任务总集数创建单集信息槽，并通过“批量设置”统一单集标题、封面和价格范围。
- 全剧付费：第 1～7 集免费，第 8 集到最后付费；不足 8 集时全部免费。
- 广告解锁：第 1 集免费，第 2 集到最后按页面“付费”状态设置，由“观看广告解锁”售卖方式决定实际解锁行为。

完成剧集设置后会点击“下一步”和确认提示，并等待页面地址进入 `step=1` 视频上传步骤。


## 多电脑同时运行

- 服务页先勾选本机要运行的账号；选择保存在本机 `electron-store` 中，不会自动启动全部账号。
- 每个应用进程生成一个 `workerId`：电脑标识经过哈希处理，再附加进程 UUID；各账号共用该进程身份。
- `POST /dramaAiRpa/kuaishou/rpa/claim` 发送 `{ accountTaskId, workerId }`。只有后台原子领取成功，且返回匹配的 `accountTaskId`、`workerId` 和正整数 `attemptCount` 后才能上传。明确的领取冲突会跳过候选；其他业务拒绝会暂停领取。
- `POST /dramaAiRpa/kuaishou/rpa/report` 发送领取时的 `workerId`、`attemptCount` 和结果。后台必须按领取者和轮次校验，并支持相同结果重复回写；旧轮次不得覆盖新轮次。
- 本机 SQLite 独立记录快手领取、提交与结果。领取响应丢失、程序中断或部分版本已提交时，该任务进入“需要核实”，不会自动重新领取。服务页可在停止服务、人工处理平台与后台状态后重新检查。
- 上报超时仅重试已保存的原结果，不会重新上传，也不会把成功改成失败。后台拒绝回写时停止自动补报，显示待处理记录；服务启动时也会补报此前账号留下的结果。
- 提交审核后至少保留任务页 10 秒，并继续验证成功。多电脑去重依赖后台原子领取与轮次校验，需所有运行电脑使用支持这些字段的新客户端。

## 一键重置遗留的上传中任务

Windows 可双击 `scripts/kuaishou-drama-reset-uploading.cmd`。默认后台账号为 `admin`，输入隐藏密码后，自动重置连续 4 小时未更新（按后台 `updateTime`）的的快手 `UPLOADING` 任务。无需 `--apply` 或停服确认参数；密码和登录 token 仅保留在本次进程内，不写入脚本、配置或日志。需要 Node.js 18+，无需安装额外依赖。

在仓库根目录运行的常用方式：

```powershell
# 默认一键处理超过 4 小时的任务，输入后台密码后执行。
node scripts/kuaishou-drama-reset-uploading.mjs

# 跳过仍需保留的任务；--skip 也是同一参数。
node scripts/kuaishou-drama-reset-uploading.mjs --skip-ids 1498

# 只处理指定 ID；此时默认不限制领取时长，跳过列表仍优先。
node scripts/kuaishou-drama-reset-uploading.mjs --ids 1500,1501

# 自定义超时时间，并限定账号。
node scripts/kuaishou-drama-reset-uploading.mjs --older-than-hours 4 --account-id 15510675085

# 指定 ID 时也可显式要求连续 4 小时未更新（按后台 `updateTime`）的。
node scripts/kuaishou-drama-reset-uploading.mjs --ids 1500,1501 --older-than-hours 4

# 按领取时间截止点筛选，无时区时按北京时间（支持 YYYY-MM-DD）。
node scripts/kuaishou-drama-reset-uploading.mjs --claimed-before "2026-10-31T06:00:00" --skip-ids 1498

# 仅预览，不登录、不修改后台。
node scripts/kuaishou-drama-reset-uploading.mjs --dry-run --skip-ids 1498
```

可将相同参数传给 `.cmd` 启动器或 `pnpm kuaishou-drama:reset-uploading`。`--username` 可指定后台账号；自动调用时可使用 `--password-stdin` 从管道传入密码，避免把密码作为命令行参数。完整帮助：`node scripts/kuaishou-drama-reset-uploading.mjs --help`。

执行前先登录后台，避免匿名调用重试接口返回 401。脚本使用 `/dramaAiRpa/kuaishou/rpa/report` 和 `/dramaAiRpa/kuaishou/accountTask/retry/{id}`：核对任务状态与领取身份，携带原 `workerId`、`attemptCount` 回写中断，再重试到 `READY`，不伪造成功或直接改库。时长是筛选规则，并非执行器心跳，仍在执行的长任务可通过跳过列表保留。

默认只自动恢复本脚本此前已回写失败、但重试未完成的 `FAILED` 遗留任务，不批量重试其他正常失败任务；显式 `--ids` 或 `--resume-failed` 可将其纳入处理。不会重置成功任务。网络异常会停止后续操作；操作记录保存在 `.cache/kuaishou-reset-时间.json`。

脚本不修改本机 SQLite；若客户端仍显示“需要核实”，请先停止服务，点击该任务的“已在后台处理，重新检查”。新一轮执行会查询并跳过平台上已提交的版本。

小时阈值按任务最后更新时间 `updateTime` 判断，支持小数，如 `--older-than-hours 1.5`。缺失或无效的更新时间会跳过。`--claimed-before` 仍是额外的领取时间筛选。

### 用户上传的版本封面

领取任务后通过 `GET /dramaAiRpa/kuaishou/dramaExtraInfo/images/detailByDramaId?dramaId=...` 读取最新的 `imagesJson`。图片对象保留上传接口返回的元数据，增加 `version`（从 1 开始，1 表示首个广告版及付费版）和 `kind`（`drama` 横版剧封面 / `episode` 竖版分集封面）。后台通过 `POST /dramaAiRpa/kuaishou/dramaExtraInfo/images/save` 保存完整列表。

每个版本、每个方向独立选择用户上传图片；缺项沿用原有封面准备 / AI 生成逻辑。旧数据没有列表或版本元数据时保持原有行为。上传图片下载或处理失败会报错，不会静默替换为 AI 图片。后台封面上传、替换、删除立即保存；新建剧目先保存获得 dramaId 再上传。
