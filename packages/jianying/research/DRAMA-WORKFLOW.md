# 前六集素材与第一集轨道自动化调查

日期：2026-11-20；目标：本机剪映专业版 11.6.0.14552，Windows x64。

## 目标流程

1. 选择整部剧目录，按集号选出第 1–6 集。缺集、重号必须报错，不能把第 10 集误当成前六集。
2. 前六集分别随机切为较长的素材片段，暂定默认 15–30 秒，可调整，保持内容完整、顺序不变，不留下过短尾段。很短的整集只保留一段。
3. 把这些片段导入剪映的传统素材面板。素材导入与加入轨道是两件事。
4. 第一集完整源视频单独加入主轨道，从时间 0 开始，不能用已经碎片化的素材替代。
5. 在剪映中执行“分离音频”，验证出现独立音频轨道。
6. 对第一集的视频轨道执行随机分割，音频暂按完整连续保留。不得用“全部轨道分割”把音频一起切开。
7. 验证素材数、视频片段数、时间线总时长和独立音频轨道，保存截图。截图暂按剪映界面留证理解，视频抽帧属于另一个输出选项。

当前已实现此流程。最新运行结果见下方补充验收；初次探索记录保留作为历史证据。

## 自动化落地路径

当前更有依据的方案是 **本地视频处理 + Windows 界面执行器**：

```text
整剧目录
  → 集号检查 → 前六集长片段随机分割 → 素材清单
  → 剪映本地导入对话框 → 校验素材面板
  → 单独把完整第一集加入主轨道
  → 原生“分离音频” → 验证独立音轨
  → 按帧定位随机切点 → 仅分割视频 → 核对总时长
  → 保存剪映窗口截图和任务记录
```

执行器应按 AutomationId/控件名称定位：素材项使用 `material.library.item.…<文件名>.apply`，加号使用 `ResourceInfoViewImportBtn`，时间线根使用 `timeline_docker_layout.timelineContainer.main_timeline_root`，视频片段使用 `MTLSVideoP:<文件名>`。这些是当前观察到的选择器候选，不能把观察时的数字元素序号固化到程序里。

Qt 弹窗、菜单、素材缩略图、轨道与播放器分别验证。快捷键应检查当前配置及系统冲突；本轮读取的 Custom1.json 不是当前默认键位的充分证据。文件名输入框实际接受 Windows 反斜杠路径，本轮直接使用正斜杠路径曾被拒绝。

下一步的验收门槛是：同一测试项目确实出现独立音频轨、多个视频片段且总时长不变，随后完成六集素材导入和截图。达成前，不应把桌面按钮命名为“全流程自动完成”。

## 首集复杂工作台：需求修正与实现

用户最终确认不合并多集，不延长视频时长。“放长”指展开时间线显示。前六集仅用于素材面板；主轨使用第一集原片。

当前实现 firstEpisodeWorkbench：主轨少量随机切口，片段长短差异明显；复制 12–16 块视频，裁出不同长度，随机铺在上方两轨，前中后都有块并留有空隙；原声分离后切段、随机重复，允许跨多条音轨重叠。中文字幕由剪映识别，顶部放置少量可用的原生特效。结束和截图时恢复素材面板。

使用用户指定的《铁锅烟火，千金满堂》实测：前六集并发生成20份长素材，连同第一集原片导入21份素材。第一集103.4秒；已验证两组不同随机排布，分别有12和16份上方复制块、三条视频轨和四至六条音频轨、24份音频块、独立字幕及原生特效。主轨保留3102帧。这里记录的是多次测试及修正结果，单次完整执行验收另存任务输出目录的实际验证结果。

新的Windows实测边界：Qt会临时不暴露过窄或不可见的轨道元素；ASR或绘制期间会出现短暂COM读取错误。只重试只读查询，不重复粘贴、拖拽或分割。新复制块采用UIA RuntimeId区分，避免轨道重排后通过坐标差分误判。拖拽使用明确按住、分步移动和释放。素材面板恢复后不发送Esc，因为本机剪映会用Esc退出最大化。

截图流程先筛选源画面，再检测实际播放器区域；复制块覆盖原片时可能改变预览，因此优先重新随机取到实际预览中检出人脸的位置。保存12张真实剪映窗口截图及各时间点记录，不合成轨道或伪造截图。
